# SciLoop 科研流程提示词使用说明

这套文档用于研究者与 Agent 的逐节点对话。它们是可独立复制的提示词，不会自动调用 SciLoop 接口或启动实验。正文中的占位符由研究者填写，已有信息也可以由 Agent 从当前对话和已提供材料中提取。

## 1. 文档与适用场景

| 文档 | 适用场景 | 本节点交付重点 |
| --- | --- | --- |
| [01-literature-review.md](01-literature-review.md) | 从新论文发现灵感，或为已有 idea 寻找相关工作 | 检索记录、论文证据、比较矩阵、研究空白 |
| [02-idea-and-feasibility.md](02-idea-and-feasibility.md) | 提出、筛选和验证研究构想 | 可证伪假设、最接近工作、可行性和最小验证方案 |
| [03-experiment-and-data-preparation.md](03-experiment-and-data-preparation.md) | 将已选构想转换成可执行实验 | 实验协议、数据划分、基线、环境和验收条件 |
| [04-experiment-execution-and-retries.md](04-experiment-execution-and-retries.md) | 执行实验、定位失败并受控重试 | 运行记录、原始结果、失败诊断、复现信息 |
| [05-results-analysis.md](05-results-analysis.md) | 判断实验结果能支持哪些结论 | 有效性检查、比较与不确定性、误差分析、论点证据表 |
| [06-paper-writing.md](06-paper-writing.md) | 根据经过核验的材料撰写论文 | 论文草稿、图表引用、贡献边界、缺口清单 |
| [07-research-retrospective.md](07-research-retrospective.md) | 对整项研究进行复盘和交接 | 假设结论、成功与失败经验、产物索引、后续路线 |
| [08-three-node-contract-prompts.md](08-three-node-contract-prompts.md) | 想在 SciLoop 之外自己跑一遍前三个节点 | 与编排层契约对齐的可粘贴提示词（字段名 + 会被校验的规则 + 自检清单） |

> **01–07 与 08 的区别**：01–07 是方法说明，字段由你自己组织；**08 是「契约对齐版」**，
> 字段名、取值、必填项与程序里强制的完全一致（含 R1–R14 的原文），适合用来对照
> 「程序到底会怎么判我这一份产出」。两者不冲突，按需要挑一份用。

## 2. 两种入口与返回路径

### 论文驱动

阅读新文章 → 文献调研 → 提取灵感 → idea 与可行性 → 实验与数据准备 → 执行实验 → 结果分析 → 论文写作 → **论文评审**。

### Idea 驱动

初步 idea → idea 节点整理为可检验假设 → 文献调研核查相关工作 → 返回 idea 节点修正与筛选 → 实验与数据准备 → 后续节点。

没有完成相关工作核查的 idea 可以进入调研，但不能直接被宣称为创新成立。调研不以“必须找到空白”为成功条件；发现已有工作解决了问题，同样是有效产出。

### 允许的返回

| 触发情况 | 返回节点 | 必须携带的信息 |
| --- | --- | --- |
| 最接近论文已有同样贡献 | 文献调研或 idea | 重合证据、仍存在的差异、是否值得继续 |
| 数据或算力不可获得 | idea 或实验准备 | 资源缺口、替代方案及其影响 |
| 环境、代码、数据处理失败 | 实验准备或执行 | 错误日志、根因假设、已尝试修复 |
| 程序成功但未达到研究预期 | 结果分析 | 完整结果，包括负结果，不将其标为技术失败 |
| 结果提示需要补对照或消融 | 实验准备 | 补实验目的、协议变更及额外预算 |
| 写作发现论点缺证据 | 调研或结果分析；必要时再准备实验 | 哪个论点缺什么证据、为何现有材料不足 |
| 预算耗尽、不可恢复或研究者终止 | 研究复盘（收尾动作） | 停止原因、已取得成果、未完成事项 |

任何节点都可以形成阶段性复盘，不必为了走完流程而制造结果。

## 3. 推荐使用方法

1. 选择当前节点，将对应文档完整复制到 Agent 对话。
2. 在输入区填入已知信息，附上可访问的论文、代码、数据说明或上一节点的交接块。
3. Agent 先复述目标、检查材料和已授权范围，再进行本节点工作。缺少关键输入时集中提出最多 3 个问题；可独立开展的部分继续进行。
4. 本节点结束时，取得规定的交付物和统一交接块。
5. 将交接块、所需文件及下一节点提示词一起提供给后续 Agent。换对话时，不假定新 Agent 能读取旧对话或本地文件。

建议由研究者维护一份研究档案，记录研究问题、版本、决策、预算、数据和文件位置。本套提示词不要求使用特定模型，也不要求在单个长对话中完成全部研究。

## 4. 所有节点共同遵守的规则

- **事实有来源。** 明确区分已核验事实、作者主张、Agent 推断、待验证假设和缺失信息。没有查到证据，不等于证实不存在。
- **保留证据链。** 论文证据保留 DOI、arXiv 版本或链接，以及页码、章节、表格、图或原文片段。实验论点保留运行、配置、数据版本和结果位置。
- **材料不足时降级。** 只取得摘要就标明“仅摘要”；全文可访问不等于所有结论已验证；翻译内容需要与原文核对。
- **执行状态真实。** 未执行、执行失败、真实执行、样例、模拟和历史回放分别标注。回放不计为新实验，模拟数值不进入实测结论。
- **保留研究者决策权。** 继承对话中已有的目标、资源边界和授权，不重复询问已确认事项。改变研究问题、主要指标、数据划分、预算上限或进行不可逆操作前，说明具体影响并取得必要确认。
- **按预算推进。** 未提供预算时先交付估算和低成本方案，不把缺省预算理解为无限额度。未经授权不运行新增付费或大规模任务。
- **尊重不确定性和负结果。** 不挑选最好的一次运行冒充总体效果，不为获得显著性反复更换种子、指标或测试集。
- **输出可接续。** 给出可访问的文件位置、已完成事项、阻塞因素、推荐下一步及其理由。未创建的文件只能列为计划产物。

## 5. 在 SciLoop 中使用的约定

SciLoop 提供文献导入与检索、全文和解析卡片、聚合对比、构想与可行性、实验记录、决策日志及 Passport 等能力。Agent 应先确认当前实际可用的材料或工具，再决定使用方式；不能仅因项目有这些名称就宣称自己已访问或调用。

- 如研究者提供了真实 `paper_id`、聚合、项目、运行或 Passport 标识，保留这些标识以便追溯；没有时使用本地编号，并明确“本地编号，非系统 ID”。
- 只读演示、模型不可用、外部来源失败或接口未接入时，说明限制并提供基于现有材料的结果，不将演示、模板或回放当成实时研究证据。
- 不在提示词交接、论文、日志或研究档案中复制 API Key、Owner Token 等凭据；需要操作能力时描述权限需求即可。
- 本文档的七个研究节点是对话组织方式，不假定与软件当前的六阶段执行枚举一一对应。
- 使用已存在的决策日志与 Passport 时引用其真实记录；无对应工具时，提供等价的研究记录模板，不伪造平台记录。

## 6. 统一状态与标识

| 状态 | 含义 |
| --- | --- |
| `ready` | 本节点的检查标准已满足，可以按建议进入下一节点 |
| `needs_revision` | 已发现需返回修改的问题；明确返回位置 |
| `needs_input` | 继续当前关键步骤需要研究者补充信息或决策 |
| `blocked` | 已知资源或工具障碍阻止关键工作；给出解除条件 |
| `stopped` | 按研究者决定或已确认的停止条件结束 |

这些状态是本套文档的交接约定，不覆盖 SciLoop 的实际接口状态。节点标识统一使用：`literature_review`、`idea_and_feasibility`、`experiment_and_data_preparation`、`experiment_execution_and_retries`、`results_analysis`、`paper_writing`、`paper_review`。流程结束时，`next_stage` 填 `end`。

> **第 7 个节点是论文评审，不是研究复盘。** 研究复盘（`research_retrospective`，见 [07](07-research-retrospective.md)）
> 是**收尾动作**：任意节点都能触发，不占节点位——中途停下、预算耗尽、假设被否定时都可以做一次。
> 不必为了「走完七个节点」而制造结果。
>
> 论文评审目前没有单独的提示词文档：评审要与生成隔离（换一个模型/另一次独立评审），
> 且需要「可写论点 / 尚不可写论点」清单作为输入——先用 [06-paper-writing.md](06-paper-writing.md)
> 末尾的缺口清单接续即可。

如需本地编号，可使用论文 `P01`、证据 `E01`、假设 `H01`、实验 `EXP01`、运行 `RUN01`、论点 `C01`。编号在同一研究中保持稳定；实验版本、修复重试和计划内重复实验分别记录。

## 7. 统一交接块

每个节点末尾都使用下面的字段。交接块应自包含：不能只给出上一对话中的“那个方案”或无法解释的 ID。建议控制在 500～1000 个中文字符；必要详情放到已确认可访问的材料中。没有信息时填写“未提供／待核验”，不要自行补全为事实。

```yaml
research_id: "研究名称或真实项目标识；没有系统 ID 时说明"
stage: "当前节点英文标识"
status: "ready / needs_revision / needs_input / blocked / stopped，选择一个"
research_question: "当前研究问题和适用范围"
selected_hypothesis: "假设、版本和可证伪条件；尚未选择则写待确定"
evidence:
  - "证据或运行编号 + 核验状态 + 支持/反驳的内容 + 可定位来源"
artifacts:
  - "已存在的文件或链接 + 内容简介 + 版本 + 接收方访问条件"
decisions:
  - "已确认决定 + 确认者/对话依据 + 尚待决定事项"
constraints: "已授权范围、剩余预算、时间、数据与计算资源限制"
blockers:
  - "阻塞或未解决问题；无则写无"
next_stage: "下一节点英文标识或 end"
next_action: "接手 Agent 首先应做的一件具体事情"
```

## 8. 如何判断这套流程有效

完成一个节点应产生可检查的成果，而不只是长篇建议。研究者应能回答：哪些信息是真实取得的、哪些判断尚未验证、为什么进入或返回某节点、下一位 Agent 从哪里继续。

默认研究交付标注：“本内容由 AI 辅助生成，需研究者自行核验”。该标注不能替代逐条证据核验。
