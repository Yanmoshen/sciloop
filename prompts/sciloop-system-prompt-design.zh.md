# SciLoop 科研 Agent 提示词设计说明

本稿面向 SciLoop 产品内的科研 Agent，覆盖文献、构思、实验、分析、写作与评审。需求已确认：节点内部常规工作自主推进，每个节点交付后等待用户验收，保留研究流程确认与高风险审批；完整吸收用户提供的 User Communication 原则。论文写作交付完整初稿、LaTeX 源文件、BibTeX 及可编译时生成的 PDF。配套正文为 `sciloop-system-prompt.zh.md`，本说明不需要送入模型。

## 设计依据

本机参考文件 `C:/Users/Yan/.codex/promts/system-prompt.md` 是 HTML 格式的 Codex 指令。借鉴其中清晰、务实、严谨的协作方式，以及先理解上下文、持续完成任务、验证结果、保护现有成果的原则。科研版本不继承工程专用前端规则、Codex 专用工具名或模型身份；其中无条件配合和将所有网络地址视为虚构的条款不适用于真实科研工具。

项目依据是当前代码与已有流程文档，主要包括 `server/services/agent_prompt_v2/`、`server/services/agent/policy.py`、`server/services/research/prompts.py`、`server/services/research/graph.py`、`server/db/models/research.py` 和 `prompts/00-workflow-guide.md`。代码中的七个节点均列入已实现节点；研究复盘作为收尾动作处理。

[OpenAI 官方 Agent 定义文档](https://developers.openai.com/api/docs/guides/agents/define-agents#shape-instructions-handoffs-and-outputs) 建议区分静态指令、依赖运行环境的动态指令与下游需要的结构化输出。本稿沿用 SciLoop 已有的分层方向，不要求改用某个 SDK 或模型。

## 三层职责

| 层 | 内容 | 维护方式 |
| --- | --- | --- |
| 固定行为层 | 科研职责、沟通、自主边界、诚信、各阶段方法与完成标准 | 配套中文 prompt |
| 运行时事实层 | 当前工具、权限、工作目录、预算、材料、已确认决定、任务与研究状态 | 由现有构造器按实际状态注入 |
| 节点契约层 | JSON 字段、枚举、必填项、证据规则、校验与迁移约束 | 继续由代码中的 schema 和校验规则生成 |

正文不固定模型、来源可用性、重试次数、预算数额或审批凭据，不复制容易漂移的完整 schema。节点模式遵守机器输出契约，对话模式按用户目标组织文字；两者共享真实性与权限要求。

## 行为选择

普通问题直接答，单项科研任务按范围完成；明确启动指令可以构成流程确认，兴趣表达和沉默不能。进入研究不需要与后续每一次日常动作绑定审批。

自主执行以实际授权为边界。平台策略允许的常规动作直接推进，审批动作提交具体方案和影响后等待，禁止动作不得换方法绕过。研究方向与协议的重大改变保留研究者决定权，已有确认不重复询问。

每个节点完成后展示成果并等待验收，用户可通过、修改或重做当前节点，或返回任意已到达的前置节点。明确的回退指令即为确认；含糊的不满先澄清目标。沿用同一研究链并保留历史版本，重新执行目标节点，将受影响的后续成果列为待复核，依据依赖关系判断需要重做的范围；未受影响的成果可以复用，回退后逐节点重新验收。

论文的完成标准是具有实质正文的完整初稿，核心论证、方法、结果、必要图表和参考文献完整，不能只交提纲、占位模板或短稿。按章节生成与修订后整稿交付，避免单次模型输出限制。关键证据或实验缺口须给出补齐方案，请用户确认后回退；未补齐时不声明写作节点完成。无编译环境可以如实交付完整源码与未验证项，不能声称已生成 PDF 或投稿就绪。

沟通部分完整覆盖用户给出的熟悉程度判断、术语适配、按目的确定解释深度、必要追问与默认值、解释原因、响应反馈、准确与尊重以及交付前自检。没有把固定章节、强制选项或每轮流程播报作为回复模板。

科研质量通过主张到证据的关系约束：文献可定位、实验真实执行、负结果保留、模型知识与核验证据分开、回放不冒充新实验、档案完整度与实际复现分开。独立评审和盲评必须由运行时真实支持，不能靠角色声明实现隔离。

## 现有技能覆盖

已检查项目内技能说明和资源，当前需求有现成技能覆盖，无需重复创建技能：

| 技能 | 写作职责 |
| --- | --- |
| `scientific-writing` | 全文组织、证据对应、方法与结果一致性、引用及文稿检查 |
| `citation-management` | 文献元数据核验、BibTeX 生成及检查 |
| `venue-templates` | LaTeX 模板、当前官方版式要求和 PDF 格式检查 |
| `scientific-visualization`、`matplotlib`、`seaborn`、`scientific-schematics` | 按需制作数据图表或方法示意图 |
| `peer-review` | 写作自检参考；独立评审仍由单独节点完成 |

`scientific-writing` 包含主张、来源、引用和一致性检查脚本；`venue-templates` 包含 LaTeX 模板与格式检查资源。模板和脚本只是辅助，不能代替真实全文写作、证据核验或人工批准。写作时先通过实际目录加载说明，按可用工具执行；检查到文件存在不等于技能已启用、依赖可用或能在研究节点中调用。技能要求人工核验的记录不可由 Agent 冒签，不把作者最终批准前的检查自动升级为投稿批准。

## 接入状态与能力边界

新版已接入首页非流式、流式和审批续答，以及 v2 提示词构造器、研究节点执行和研究对话措辞。共享加载器为 `server/services/system_prompt.py`，运行正文为 `server/services/prompts/sciloop-system-prompt.zh.md`，后端 Docker 镜像和 Python 安装包均携带该资源。根目录的同名文件作为审阅副本保留，测试检查两份正文一致；后续调整需同步两份文件并重启后端。

已清理首页的默认同意、每轮强制研究邀请、固定提问格式、每轮阶段播报及旧输出模板；已有会话邀请仍由程序要求明确接受。v2 默认预算提高到 16000 字符，完整固定指令始终保留。研究节点保留真实 JSON schema 和运行时材料边界，移除论文短稿与自动替用户锁定方向的要求；写作补充文档同步采用完整初稿和默认 LaTeX、BibTeX 交付标准。

本次是提示词接入，没有扩展编排、存储和导出能力。以下要求仍需程序实现，不能将指令替换等同于功能验收：

1. 写作契约仍以 `content_md` 为核心。分章节持久化、完整 LaTeX 源文件包、真实技能调用与编译导出需进一步接入；当前 Agent 必须如实报告能力限制，不虚报文件或 PDF。
2. 研究图仍只允许部分回退边，并有回退次数和携带信息约束。任意前置节点回退、当前节点重做、历史版本和下游依赖待复核尚未由本次修改补齐。
3. 编排器仍会在模型判断 done 时记录向下一节点的迁移。每节点用户验收与程序迁移必须进一步协调；本稿要求等待用户验收，但不能依赖提示词阻止程序自身迁移。
4. 工具权限、审批、预算、停止任务和独立评审隔离继续由实际程序控制，提示词不提供额外权限或能力。


## 建议的接入验收

用少量有代表性的场景验证行为：普通论文问答不启动流程；明确启动指令不重复确认；未回答流程确认保持等待；常规授权任务在节点内持续执行，节点交付后等待验收；高风险动作等待有效审批；找不到文献时交付缺口而不造引用；实验未运行时不写成功；负结果不被包装；JSON 节点产出符合接入后的实际契约；停止后不再发起新动作。

增加本次需求的验收：明确回退到任意已到达前置节点时不重复询问；含糊不满先澄清；当前节点可重做；旧版本保留且受影响下游列为待复核；无关成果不强制重跑；回退后逐节点重新验收；写作实际使用可用技能并交付完整 LaTeX、BibTeX 和必要资源；缺编译环境时不虚报 PDF；关键证据缺口未补齐时不声明写作完成。

以上场景是完整功能的验收目标。本次完成共享正文、一致性、旧规则移除、JSON 契约和动态预算的自动化检查；未调用真实模型进行全流程行为评测。

验证记录：直接相关的 74 项测试通过；扩展研究模块检查为 104 项通过、2 项失败。失败位于 `test_run_lifecycle.py`，旧测试期望中断任务为 `failed`，而当前及 HEAD 中代码均返回 `pending`，与此次提示词修改无关。修改模块的 ruff 检查通过。本机统一启动器已重启后端，服务健康检查通过。
